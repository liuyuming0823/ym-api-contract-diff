# 类型族归一化与高风险项判定细则

本文件是接口字段比对的硬性知识，按需加载。判定逻辑以此为准，不要凭直觉归类。

## 一、字段名归一化

目标是让「同一个逻辑字段、只是写法不同」能被识别为同字段。

- 驼峰 ↔ 下划线互转：`userId` ⇄ `user_id`、`orderDetailList` ⇄ `order_detail_list`
- 归一形式建议统一成下划线（`user_id`），并在「归一化对照表」里同时保留两侧原写法
- 仅大小写不同（如 `ID` 与 `id`）也按同一字段处理，但要在对照表标注「仅大小写不同，部分语言区分大小写需确认」
- 前缀差异（如 `data.userName` 与 `userName`）按末级字段名归并，路径差异单独说明

注意：归一化只用于「判断是不是同一个字段」，原始字段名在差异表与报告中一律保留，不替用户改写。

## 二、类型族对照表

精确类型不可丢弃，但比对时先按族归类，快速筛出明显不一致；落入同族的再回看精确类型。

| 类型族 | 归入的精确类型（常见写法） | 备注 |
|---|---|---|
| 数值族 | int、Integer、long、Long、short、byte、number、float、double、BigDecimal、bigint、decimal | 浮点与整数都进数值族，但精确类型必须回看（见高风险项） |
| 字符串族 | String、string、char、text、varchar、uuid（无类型标注时按字符串） | 日期、枚举若无独立类型也先落这里，再走高风险判定 |
| 布尔族 | boolean、Boolean、bool | — |
| 对象族 | object、Map、实体类、嵌套 JSON、struct | 嵌套对象需递归展开成路径字段 |
| 数组族 | array、List、[]、Set、Collection | 标注元素类型，如 `List<Long>` |
| 日期时间族 | Date、DateTime、Timestamp、LocalDateTime、time、Instant | 若只标 String 但语义是日期，见高风险项 |

归一结果判定：
- 两族不同 → 直接判「类型不一致」，进差异表
- 同族但精确类型不同 → 先归为「同族待查」，再按下方高风险项逐条核对

## 三、高风险项清单

以下每一项出现即单列，不得被类型族归一掩盖。

### 1. Long / bigint 超出 JS 安全整数
- 判定：任一侧类型为 `long/Long/bigint`，且该字段是 ID、订单号、金额分等大整数
- 影响：前端 JavaScript `Number` 安全整数上限为 2^53 - 1（9007199254740991），超出会静默丢失精度，ID 错位导致查不到数据
- 建议：后端以字符串传输，或前端用 `BigInt`/字符串库处理；在报告中标注具体字段

### 2. 日期格式不明确
- 判定：字段语义为时间，但类型只标 `String`/`number`，或未标注时区；或一侧时间戳一侧格式化字符串
- 影响：前端按固定格式解析失败，`new Date()` 对不含时区的时间戳按本地时区解释，跨时区错 8 小时常见
- 建议：明确格式（`yyyy-MM-dd HH:mm:ss` / `yyyy-MM-dd'T'HH:mm:ssXXX`）与时区；时间戳需注明单位（秒/毫秒）

### 3. 枚举值未对齐
- 判定：逻辑为枚举的字段，两侧取值集合不同（如前端 `0/1/2` 后端 `ENABLED/DISABLED/DELETED`），或一方用魔法数字另一方用字符串
- 影响：前端按自己枚举渲染，收到未知值直接显示空白或崩溃
- 建议：建立统一的枚举映射表，要求任一侧做转换并标注哪侧负责

### 4. 金额用浮点
- 判定：金额/价格/比例类字段类型为 `float/double`，而非整数分或 `decimal/BigDecimal`
- 影响：二进制浮点无法精确表示十进制小数，累加出现 `0.1 + 0.2 != 0.3` 类误差，财务对账出错
- 建议：改用整数（最小货币单位）或十进制类型；在报告中强制单列

### 5. 空值口径不一致（跨字段）
- 判定：同一字段一侧在缺值时返回 `null`，另一侧直接不返回该 key
- 影响：前端若用 `obj.field` 取值，缺失 key 得到 `undefined` 而非 `null`，判空逻辑分支不同，可能触发渲染异常
- 建议：统一约定「缺失即不返回」或「缺失返回 null」，并在接口文档写明

## 四、必填口径判定

- 「必填」以接口文档 / DTO 注解（`@NotNull`、OpenAPI `required: true`）为准；无标注时按示例值是否出现推断并标注「推断」
- 一侧必填一侧可选 → 进差异表「必填口径不一致」，影响通常是：可选侧不传时必填侧校验失败报错
- 不要因为「字段两侧都有」就默认必填一致，必须各自查口径
